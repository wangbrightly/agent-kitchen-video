# AI 厨房 — 解说词（用户的文案，按 tts 格式重排；竖线只切字幕）
# CHAPTER 1 大脑和厨师
先看厨房里最重要的两样东西
一个是厨师的大脑
一个是完整站在厨房里的厨师

大脑|是 LLM
厨师|是 Agent
这两个不是一回事

这位厨师的颅顶打开了|里面露出一颗灰色的大脑
那就是 LLM|大语言模型
它负责理解要求|分析问题|做判断|想出下一步怎么做

但大脑本身没有手
不能拿刀|不能开火|不能打开冰箱
它只能思考|然后说出自己的判断

站在厨房里的整个人|才是 Agent|智能体
他有大脑|有手|有记性|有菜谱|也有自己的岗位职责
所以|LLM 是大脑

Agent 是完整的厨师
大模型负责想
智能体负责把事情做完

同一个大脑|装进不同的厨师身体
接上不同的工具和规则
就可能成为完全不同的智能体

有的厨师负责写代码
有的厨师负责分析数据
有的厨师负责处理邮件

差别不一定在大脑
而在于它被安排做什么|又被允许使用什么

# CHAPTER 2 岗位与工具
每位厨师上岗前|都会拿到一张岗位说明
上面写着|你是谁|你负责什么
应该遵守哪些规则|遇到问题时|优先怎么处理

这相当于智能体的系统提示词
它决定了厨师的身份|目标和工作边界
但只有岗位说明|厨师仍然做不了多少事

因为他还没有手
厨房里的刀|锅|勺|夹子|铲子
就是 Tool|工具
## gap 20

工具让智能体可以执行具体动作
刀可以切菜|锅可以加热|夹子可以夹取
在数字世界里|工具可能是

读取文件
搜索网页
运行代码
查询数据库
发送邮件

模型不能直接使用这些工具
它只能提出调用请求
比如
## gap 20

“请读取这份文件”
“请查询这条数据”
“请运行这段代码”

外部程序真正执行动作
再把结果递回厨房
厨师看到结果之后|继续判断下一步

所以工具解决的是
“这个智能体能做什么？”

# CHAPTER 3 菜谱和记忆
有了手|还要知道做菜的方法
台面左边那个插满卡片的盒子|就是 Skill|技能
每张卡片|都是一套可重复使用的做法

比如
如何整理一份表格
如何排查一个程序错误
如何生成一份周报
如何处理一封客户投诉

技能不是某一个动作
而是一整套流程
先做什么|再做什么|遇到异常怎么办|最后如何交付结果

工具告诉厨师|手里有哪些器械
技能告诉厨师|这些器械应该怎样配合
平时|厨师不需要把所有菜谱都摊在桌上

只看见卡片标题就够了
真正要做那道菜时|再把对应卡片抽出来阅读
这样可以节省大脑的注意力

厨房最左边的冰箱门上|贴着四张纸
那就是 Memory|记忆
上面可能写着

客人不吃香菜
这个项目使用哪种代码规范
上次任务做到哪一步
某个文件放在什么位置

记忆保存的是|跨时间仍然有用的信息
今天知道的事|明天还能继续使用
但记忆也可能出错

如果便签写错了|厨师明天就可能继续照着错误信息做
所以记忆需要被检查|更新和清理
到这里|一位厨师已经拥有

大脑|岗位职责|工具|菜谱和记忆
但他什么时候开始工作|还需要有人或某种机制来触发

# CHAPTER 4 命令与钩子
台面上有一个铜铃
客人按一下|就会打出一张小票
小票上的任务|就是 Command|命令
## gap 20

它由人主动发起
比如
“帮我整理这份数据”

“检查这个项目里的错误”
“把这段文字翻译成英文”
人按铃|厨师开始工作

这就是 Command 的特点
由人决定什么时候做什么
墙上还有另一套装置

表盘负责监测温度
顶上的铃铛负责报警
中间垂下来一根探针|持续观察厨房里的变化

这就是 Hook|钩子
它不需要人每次按铃
只要某个条件发生|就自动触发动作

比如
文件保存时|自动备份
代码提交时|自动测试
温度过高时|自动报警
## gap 20

收到新邮件时|自动处理附件
所以|人按铃|是 Command
机器根据条件自动触发|是 Hook
## gap 20

Command 说的是
“现在开始做这件事”
Hook 说的是|“只要这件事发生|就自动执行那个动作”

有些 Hook 可以直接启动工具
有些 Hook|也可以进一步唤起智能体

# CHAPTER 5 标准接口
厨房墙上有一排标准插座
旁边连着一条送料轨道
这就是 MCP

MCP 不是刀|也不是厨师的手
它更像一套统一的连接规格
外部服务接入之后|可以按照统一方式介绍自己

我能提供什么能力
调用我需要哪些参数
我会返回什么结果

这样|智能体就能接入外部的工具和数据
比如
文件系统
## gap 20

数据库
搜索服务
企业内部系统
第三方应用

MCP 解决的不是“工具是什么”
而是“工具如何接进来|又如何被发现和调用”
所以|手里的刀锅铲|是 Tool
## gap 20

墙上的标准插座|是 MCP
工具是具体能力
MCP 是连接这些能力的协议

没有工具|插座接不出任何动作
没有统一的连接方式|每接一家外部服务都要重新改造厨房

# CHAPTER 6 整箱采购
如果每次安装能力|都要一件一件配置
拿一把刀|配一张菜谱|再接一个外部服务
会非常麻烦

于是有人把相关东西装进一只木箱
箱子里可能有
几件工具

几张技能卡
一些记忆模板
连接外部服务的配置
自动触发规则

这整箱东西|就是 Plugin|插件
插件本身不是厨师
也不是大模型

它更像一个能力安装包
把一组相关资源|一次性送进厨房
装上一个代码插件|厨师可能获得读写文件|运行测试和代码检查能力

装上一个数据插件|厨师可能获得表格处理|数据库查询和图表生成能力
插件解决的是
“怎么一次装齐一组能力？”

现在|把所有东西放回厨房
一位厨师|是 Agent
厨师的大脑|是 LLM
## gap 20

厨师的岗位职责|是系统提示词
厨师手里的刀锅铲|是 Tool
台面上的菜谱卡盒|是 Skill
## gap 20

冰箱门上的便签|是 Memory
台面上的铜铃|是 Command
墙上的烟感和恒温器|是 Hook
## gap 20

墙上的标准插座|是 MCP
地上的整只木箱|是 Plugin
它们之间的关系其实很简单

一位厨师|也就是 Agent
里面包含
大脑|负责思考

工具|负责行动
技能|负责遵循流程
记忆|负责保留信息
岗位职责|负责规定身份和边界

而厨师之外还有三件事
手从哪里接进来|靠 MCP
谁来启动任务|人按是 Command|机器触发是 Hook

怎么一次获得一组能力|靠 Plugin
所以|智能体不是单独的一颗大脑
也不是某一个工具

而是大脑|工具|技能|记忆|规则和运行机制共同组成的完整系统
大脑决定它会不会想
工具决定它能不能做

技能决定它会不会按流程做
记忆决定它能不能延续过去
而厨房怎么搭|就决定了这位厨师最终能做什么
