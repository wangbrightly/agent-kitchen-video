## §执行摘要

1. LLM 只负责推理和生成，不直接执行动作；Claude API 的 client tool 由你的程序执行，server tool 由 Anthropic 基础设施执行。https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview
2. Tool 是“动作接口”：定义三件套是 `name` / `description` / `input_schema`；模型回 `tool_use` + `stop_reason: "tool_use"`，程序回 `tool_result`。https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview
3. MCP 不是工具，是“把外部工具/数据接进来”的开放协议；一个 MCP server 可以暴露多个 tool，常见传输是 stdio 与 Streamable HTTP。https://modelcontextprotocol.io/docs/learn/architecture
4. Agent 是“自己决定步骤并调用工具”的系统，和“固定代码路径”的 workflow 相对；Claude Code 的 harness 提供工具、上下文和循环。https://www.anthropic.com/engineering/building-effective-agents
5. Skill 是“按需加载的说明书/程序性知识”：平时只有 name + description 进上下文（官方估算约 100 tokens），触发时才读 SKILL.md 全文（官方估算 <5k tokens）。https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview
6. Command 是人用 `/name` 发起的可复用指令；在 2026 年的 Claude Code 里，自定义 command 已并入 skill，两种文件都生成 `/name`。https://code.claude.com/docs/en/slash-commands
7. Hook 是 harness 在生命周期事件上自动执行的代码，不是模型“决定要不要跑”；PreToolUse 可以用 exit code 2 阻断工具调用。https://code.claude.com/docs/en/hooks
8. Memory 是跨会话的文件（CLAUDE.md、auto memory、API 的 memory tool），不是模型权重；CLAUDE.md 是上下文，不是强制配置。https://code.claude.com/docs/en/memory
9. Plugin 是分发容器，把 skills/commands、agents、hooks、MCP servers 打包成一个安装单元；它本身不行动，行动的是 agent。https://code.claude.com/docs/en/plugins

## §关系主线（建议口播）

LLM（会想）→ Agent（自己决定）→ Tool（动手）→ MCP（把外部工具接进来）→ Skill（教它怎么做）→ Command（人点单）→ Hook（到点自动做）→ Memory（记住上次做到哪）→ Plugin（整套打包）。

口播时补一句：这条链不是单向流水线。真实运行时是循环——Tool 的结果回到 Agent，Agent 再判断下一步；所以“厨师做一道菜”会来回很多次，而不是从第一条走到最后一条。循环的官方描述见 https://code.claude.com/docs/en/agent-sdk/agent-loop

### 厨房比喻映射（建议）

| 概念 | 厨房角色 | 一句话理由 | 讲的时候补一句 |
|---|---|---|---|
| LLM | 厨师的厨艺/大脑 | 会判断、会配方，但不动手 | 没有工具时只能“说菜”，不能“做菜” |
| Agent | 厨师本人 | 有目标，自己决定先切菜还是先烧水 | 厨师 = 厨艺 + 手脚 + 目标感；Agent = LLM + 工具 + 循环 |
| Tool | 厨具（刀、灶、冰箱） | 每个工具有名字、用途说明、参数 | 模型只递“我要用这把刀”的申请，动手的是厨房 |
| MCP | 标准插座/传菜窗口 | 让外部设备按统一接口接进来 | MCP 不是厨具；它让外面的料理机也能被厨房调用 |

| Command | 顾客点菜单 | 人喊 `/宫保鸡丁`，厨房照单做 | 人触发；不是到点自动跑 |
| Hook | 厨房自动安全装置 | 烟雾一响就开排风，不跟厨师商量 | 触发是确定的；但 prompt 型 hook 内部仍可能问模型 |
| Memory | 冰箱便签/交接班本 | 跨班次保留上次做到哪 | 便签是提醒，不是锁；硬规则要用 Hook |
| Plugin | 整套中央厨房设备包 | 把菜谱、厨师、自动装置、接口打包成一个安装单元 | 容器不行动，行动的是里面的厨师（Agent） |

## §九个概念的官方定义

### 1. LLM

一句话定位：LLM 是“会推理、会生成”的大脑；它本身不执行动作。

官方原句：

> “Large language models (LLMs) are AI language models with many parameters that are capable of performing a variety of surprisingly useful tasks. These models are trained on vast amounts of text data and can generate human-like text, answer questions, summarize information, and more.”

怎么讲：LLM 的输出是文本或结构化的调用请求；真正“做事”的是外面的程序。Claude Code 文档把这件事说得更直白：“Without tools, Claude can only respond with text.” 所以 LLM 是厨师的厨艺，不是厨师的手。

出处：https://platform.claude.com/docs/en/about-claude/glossary ；https://code.claude.com/docs/en/how-claude-code-works

### 2. Agent

一句话定位：Agent 是“自己决定下一步”的行动者；不是某个模型，而是模型 + 工具 + 循环 + 运行环境。

官方原句：

> “Agents, on the other hand, are systems where LLMs dynamically direct their own processes and tool usage, maintaining control over how they accomplish tasks.”

Agent SDK 的定义更具体：

> “An agent is an application that completes a task by planning its own steps and calling tools that read files, run commands, or edit code.”

怎么讲：Agent 与 workflow 的分界是“谁决定路径”。workflow 走预设代码路径；Agent 每一轮根据工具结果重新判断。Claude Code 本身是 harness：它“provides the tools and manages the context the model sees”。subagent 则是被委派的独立工人：自己的上下文窗口、自己的系统提示词、自己的工具访问与权限。

出处：https://www.anthropic.com/engineering/building-effective-agents ；https://code.claude.com/docs/en/agent-sdk/overview ；https://code.claude.com/docs/en/glossary ；https://code.claude.com/docs/en/sub-agents

### 3. Tool

一句话定位：Tool 是“动作接口”——模型说“我要做这个”，外层程序负责真正做。

官方原句：

> “Tool use (also called function calling) lets Claude call functions that you define or that Anthropic provides. Claude determines when to call a tool based on the user's request and the tool's description. It then returns a structured call that your application runs (client tools) or that Anthropic runs (server tools).”

调用回路：

> “Claude responds with `stop_reason: "tool_use"` and one or more `tool_use` blocks. Your code runs the operation and sends back a `tool_result`.”

怎么讲：工具定义就是三件套：`name`（叫什么）、`description`（什么时候用、怎么用）、`input_schema`（参数长什么样）。模型返回 `tool_use`（带 `id`、`name`、`input`），程序执行后把结果包成 `tool_result`（带 `tool_use_id`）回填。OpenAI 的 function calling 是同一机制的另一套命名：2023-06-13 从 `functions` / `function_call` 起步，后来在 Chat Completions 里改成 `tools` / `tool_choice`；官方规范明确写着 `functions` “Deprecated in favor of `tools`”。

出处：https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview ；https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools ；https://openai.com/index/function-calling-and-other-api-updates/ ；https://developers.openai.com/api/docs/guides/function-calling

### 4. MCP

一句话定位：MCP 是“工具与数据的接入协议”，不是工具本身；它让外部 server 按统一方式把工具递给 AI 应用。

官方原句：

> “MCP (Model Context Protocol) is an open-source standard for connecting AI applications to external systems.”

> “Think of MCP like a USB-C port for AI applications.”

怎么讲：MCP 用 JSON-RPC 2.0，角色是 Host / Client / Server。一个 server 可以提供三类原语：Tools、Resources、Prompts；客户端用 `tools/list` 发现工具，再用 `tools/call` 调用。一个 server 可以暴露多个 tool。传输最常见的是 stdio（本地进程）和 Streamable HTTP（远程）。MCP 只负责“怎么交换上下文”，不规定 AI 应用怎么使用 LLM，也不替模型做判断。

出处：https://modelcontextprotocol.io/docs/getting-started/intro ；https://modelcontextprotocol.io/specification/2025-06-18 ；https://modelcontextprotocol.io/docs/learn/architecture ；https://modelcontextprotocol.io/specification/2025-06-18/server/tools

### 5. Skill

一句话定位：Skill 是“按需加载的说明书/程序性知识”；不是工具，不直接执行动作。

官方原句：

> “Skills are reusable, filesystem-based resources that give Claude domain-specific expertise: workflows, context, and best practices that turn a general-purpose agent into a specialist.”

渐进式披露：

> “until a Skill is triggered, only its name and description occupy context.”

怎么讲：Skill 是一个目录，里面有 `SKILL.md`；`SKILL.md` 必须有 YAML frontmatter 的 `name` 和 `description`。启动时只把 name + description 放进系统提示（官方估算约 100 tokens）；Claude 判断相关时，才用 bash 读 `SKILL.md` 全文（官方估算 <5k tokens）；里面引用的参考文件、脚本再按需读，脚本的代码本身不进上下文，只有输出进上下文。Skill 可以包含让 Claude 执行的脚本，但“Skill 本身”不是 API 里的 tool schema。

出处：https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview ；https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills

### 6. Command

一句话定位：Command 是“人用 `/name` 发起的可复用指令”；在现在的 Claude Code 里，它和 Skill 同源。

官方原句：

> “A reusable instruction you invoke by typing `/name` in the prompt.”

合并事实：

> “Custom commands have been merged into skills. A file at `.claude/commands/deploy.md` and a skill at `.claude/skills/deploy/SKILL.md` both create `/deploy` and work the same way.”

怎么讲：把 Command 想成“顾客点菜单”——人喊 `/宫保鸡丁`，厨房照单做。它和 Hook 的分界是触发者：Command 由人（或模型按 skill 描述）发起，Hook 由生命周期事件触发。注意一个细节：Skill 默认也可能被模型自动加载；要只允许人用 `/name` 触发，设 `disable-model-invocation: true`。另外，产品文案现在把 “Slash commands” 简称为 “Commands”。

出处：https://code.claude.com/docs/en/glossary ；https://code.claude.com/docs/en/slash-commands

### 7. Hook

一句话定位：Hook 是“生命周期上的自动装置”，由 harness 执行，不是模型临时决定要不要跑。

官方原句：

> “Hooks are user-defined shell commands, HTTP endpoints, MCP tool calls, LLM prompts, or subagents that execute automatically at specific points in Claude Code's lifecycle.”

最关键的区分：

> “Hooks are code that the harness runs rather than instructions to Claude.”

怎么讲：常见事件有 `PreToolUse`（工具调用前）、`PostToolUse`（工具调用后）、`UserPromptSubmit`（用户提交提示词）、`Stop`（一轮结束）、`SessionStart`（会话开始）。`PreToolUse` 可以阻断工具调用；退出码 2 就是“停，别做”。Hook 在主对话之外执行，默认不占上下文；只有它返回内容时，才会进入上下文。需要补充的例外：command / HTTP / MCP 三类 hook 是确定性执行；prompt / agent 两类 hook 内部会调用模型判断，所以“触发确定”不等于“判断一定不用模型”。

出处：https://code.claude.com/docs/en/hooks ；https://code.claude.com/docs/en/features-overview ；https://code.claude.com/docs/en/glossary ；https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more

### 8. Memory

一句话定位：Memory 是“跨会话保留的文件”，不是模型权重；它在每次会话开始时被重新注入。

官方原句：

> “Each Claude Code session begins with a fresh context window. Two mechanisms carry knowledge across sessions: CLAUDE.md files... Auto memory...”

最关键的边界：

> “Claude treats them as context, not enforced configuration. To block an action regardless of what Claude decides, use a PreToolUse hook instead.”

怎么讲：Claude Code 的 Memory 有两套：你写的 `CLAUDE.md`（managed / user / project 三个层级）和 Claude 自己写的 auto memory（每次加载 `MEMORY.md` 的前 200 行或 25KB）。API 侧还有一个同名的 memory tool：`{"type": "memory_20250818", "name": "memory"}`，它是 client-side 的——Claude 只发文件操作请求，真正存储在你的应用里，路径前缀是 `/memories`。两种 Memory 都不是“模型记住了”，而是“文件被重新读进来了”。

出处：https://code.claude.com/docs/en/memory ；https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool

### 9. Plugin

一句话定位：Plugin 是“打包与分发容器”；它本身不行动，行动的是里面的 agent。

官方原句：

> “A Claude Code plugin is a directory of skills, agents, hooks, MCP servers, or other components that Claude Code installs and loads as one unit.”

Marketplace 的定义：

> “a catalog that lists plugins and where to fetch each one”

怎么讲：一个 plugin 通常有 `.claude-plugin/plugin.json`，里面可以放 `skills/`、`commands/`、`agents/`、`hooks/hooks.json`、`.mcp.json` 等组件。它的价值是“一次安装，整套生效”，并且可以按命名空间共存，比如 `/my-plugin:review`。Marketplace 不是托管商店，而是一个带 `.claude-plugin/marketplace.json` 的仓库或目录。2025-10-09 发布时的官方说法是打包 slash commands、subagents、MCP servers、hooks；后来 Skills 成为新组件的推荐写法，commands 逐渐被 skills 取代。

出处：https://code.claude.com/docs/en/plugins ；https://code.claude.com/docs/en/plugins/components ；https://claude.com/blog/claude-code-plugins

## §容易讲错的地方

### 1. “模型自己执行工具”

错说法：模型看到问题，自己把工具跑了，再把结果告诉自己。

正确说法：模型只产出 `tool_use` 调用请求；执行者是外层程序（client tool）或 Anthropic 的基础设施（server tool）；执行结果以 `tool_result` 回填，模型再基于结果继续。官方原句：“It then returns a structured call that your application runs (client tools) or that Anthropic runs (server tools).”

出处：https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview

### 2. “MCP 就是一个工具”

错说法：MCP 是某个具体的工具，装上它模型就会用某个功能。

正确说法：MCP 是协议/标准，不是工具。一个 MCP server 可以提供多个 tool，还可以提供 resources 和 prompts。官方原句：“This array-based structure allows servers to expose multiple tools simultaneously...” 以及 “MCP focuses solely on the protocol for context exchange”。

出处：https://modelcontextprotocol.io/docs/learn/architecture ；https://modelcontextprotocol.io/specification/2025-06-18

### 3. “Skill 就是 Tool，或者 Skill 会直接执行代码”

错说法：Skill 是模型可以调用的函数，和 Tool 是一回事。

正确说法：Skill 是加载进上下文的说明书/程序性知识；它不直接执行。Skill 可以包含脚本，Claude 可以用 bash 去跑这些脚本，但“Skill 本身”不是 API 的 tool schema。官方原句：“Skills are reusable, filesystem-based resources that give Claude domain-specific expertise”；“until a Skill is triggered, only its name and description occupy context.”

出处：https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview ；https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills

### 4. “Command 和 Skill 是两套东西”

错说法：Command 是命令，Skill 是技能，二者互不相干。

正确说法：在 2026 年的 Claude Code 里，自定义 command 已经并入 skill；`.claude/commands/deploy.md` 和 `.claude/skills/deploy/SKILL.md` 都会生成 `/deploy`，工作方式相同。commands 是旧格式，skills 是新写法。官方原句：“Custom commands have been merged into skills.”

出处：https://code.claude.com/docs/en/slash-commands ；https://code.claude.com/docs/en/plugins/components

### 5. “Hook 是模型判断后决定跑不跑”

错说法：Hook 是提示词，模型觉得该跑才跑。

正确说法：Hook 在固定的生命周期事件上由 harness 触发，不是模型临时决定。官方原句：“Hooks are code that the harness runs rather than instructions to Claude.” `PreToolUse` 还可以用 exit code 2 直接阻断工具调用。需要补充的例外：prompt / agent 两类 hook 内部会调用模型判断，但“触发”仍然是确定的事件触发。

出处：https://code.claude.com/docs/en/hooks ；https://code.claude.com/docs/en/glossary ；https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more

### 6. “CLAUDE.md 写了就一定会遵守”

错说法：把规则写进 CLAUDE.md，模型就一定会照做。

正确说法：CLAUDE.md 是上下文，不是强制配置。官方原句：“Claude treats them as context, not enforced configuration. To block an action regardless of what Claude decides, use a PreToolUse hook instead.” 要“绝对不许发生”，用 Hook 或权限规则，不要只用提示词。

出处：https://code.claude.com/docs/en/memory ；https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more

### 7. “Memory 是模型记住了/模型权重更新了”

错说法：聊得越多，模型就自动记住，下次不用再说。

正确说法：Memory 是文件。Claude Code 每次会话开始是全新上下文，靠 CLAUDE.md 和 auto memory 重新注入；API 的 memory tool 是 client-side，Claude 只发文件操作请求，数据存在你自己的存储里。官方原句：“The memory tool operates client-side: Claude requests file operations, and your application runs them.”

出处：https://code.claude.com/docs/en/memory ；https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool

### 8. “Plugin 是另一种 Agent / Agent 就是 LLM”

错说法：Plugin 会自己干活；或者 Agent 就是换了个名字的 LLM。

正确说法：Plugin 是打包/分发容器，可以包含 agent，但本身不行动；Agent 是行动者，是 LLM + 工具 + 循环 + 运行环境。官方原句：Plugin 是 “packaged as a single installable unit”；Agent 是 “an application that completes a task by planning its own steps and calling tools”。LLM 只是大脑，没有工具只能输出文本。

出处：https://code.claude.com/docs/en/plugins ；https://code.claude.com/docs/en/agent-sdk/overview ；https://code.claude.com/docs/en/how-claude-code-works

8. 各模型/版本的 token 数字（如每个 Skill 约 100 tokens）是官方当前文档的估算，会随实现变化：引用时加“官方估算”，不要说成固定值。
